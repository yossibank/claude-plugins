# session-next-steps

ターンが終わるたびに、次にすることを 3 つまで選び、入力欄の上にボタンで出すプラグイン。

## ✨ 機能

| できること | 中身 |
| --- | --- |
| 選ぶ | メインのターンが終わるたびに、そのターンのツールの呼び出しと git の状態から、決まった規則で候補を選ぶ。モデルは呼ばない |
| 出す | 候補を、理由と一緒に入力欄の上の帯に並べる。当てはまるものが無ければ、帯を出さない |
| 入れる | ボタンを押すと、その指示の文を入力欄に入れる。送信はしない |
| 消す | 次の指示を送った時と、次のターンが始まった時に帯を消す。`0` で隠すと、次のターンの終わりまで出さない |
| 待たせない | git と gh は、ターンの終わりを待たせずに走らせる。走らせるのは読むだけのコマンドに限る |
| 失敗を知らせる | 調べるのに失敗した時と、入力欄に入れられなかった時は、トーストで知らせる |

## 📦 入れ方

```sh
/plugin install session-next-steps --marketplace yossibank/claude-plugins
```

[ルートの README の入れ方](../../README.md#-入れ方)

## 🧭 候補の規則

上から優先して、当てはまったものを `maxSteps` 個まで出す。

| 順 | 当てはまる時 | ボタン | 入力欄に入る文 |
| --- | --- | --- | --- |
| 1 | このターンで最後に走らせたテストかビルドが失敗した | 落ちた所を直して | `<当たったコマンド> の落ちた所を直して` |
| 2 | このターンでファイルを書き換え、その後にテストかビルドを走らせていない | `<testCommand>` を走らせて | ボタンと同じ |
| 3 | まだ commit していない変更がある | 変更を commit して | ボタンと同じ |
| 4 | push していない commit がある | push して | ボタンと同じ |
| 5 | 既定のブランチでなく、push 済みで、PR が無い | PR を作って | ボタンと同じ |
| 6 | 文脈の埋まり具合が `contextPercent` 以上 | /handoff で区切る | `/handoff` |

細かい決まりは次のとおり。

| 場面 | 決まり |
| --- | --- |
| テストかビルド | Bash のコマンドを区切り（`&&`・`;`・`\|`）ごとに `checkPattern` に当てる。引用の中の字（commit の文など）は当てない |
| 失敗 | Bash が失敗を返した時。`make test \| tee log` は `tee` の結果になるので、失敗と分からない（`set -o pipefail` を付ける） |
| 失敗の後に書き換えた | 直している途中とみなし、1 は出さずに 2 だけを出す |
| 書き換え | `Edit`・`MultiEdit`・`Write`・`NotebookEdit` が成功した回。メインの呼び出しだけを数え、サブエージェントの分は数えない |
| upstream が無いブランチ | どのリモートにも無い commit を数える。リモートが無いリポジトリでは、push を勧めない |
| 既定のブランチ | `origin/HEAD` の指すブランチ。分からない時は `main` と `master` |
| PR | `gh pr view --json number` で確かめる。`gh` が無い・5 秒で返らない・ほかの理由で失敗した時は、黙って飛ばす。PR があると分かったブランチは、次から確かめない |
| 文脈 | 要約に入る手前までの窓に対する割合。session-handoff と同じ測り方 |
| リポジトリの外 | 3〜5 は出さない |

## 🖥️ 帯

```
➡ 次の一手
1: make test を走らせて  3 ファイルを書き換えた後、まだ確かめていない
2: 変更を commit して    未 commit 5 件
3: push して             push していない commit 2 つ
0: 隠す
```

理由は薄い字で出す。幅が狭い時は理由を切り、もっと狭い時は理由を出さない。

| キー | ボタン |
| --- | --- |
| `1`〜 | その行の指示の文を入力欄に入れる |
| `0` | 帯を隠す |

数字のキーは、帯がキーを持っている間だけ効く。帯がキーを持つのは、`ctrl+x tab` を押した後か、帯をクリックした後である。入力欄が空の時は、そのまま数字を打っても帯のボタンが押される。ボタンのクリックは、いつでも効く。

`/handoff` は [session-handoff](../session-handoff/README.md) のコマンドである。入れていない時は、この候補は使えない。`contextPercent` を `100` にすると、文脈がいっぱいになるまで出ない。

## 🔧 設定

| 名前 | 中身 |
| --- | --- |
| `maxSteps` | 帯に出す候補の上限。初めは `3` |
| `testCommand` | 規則 2 で走らせるよう勧めるコマンド。初めは `make test`。`checkPattern` に当たるものにする（当たらないと、走らせた後も勧め続ける） |
| `checkPattern` | テストとビルドのコマンドの正規表現。初めの値は `make` の `test`・`build`・`verify`・`check`・`lint`・`types` を含むターゲット、`npm`・`pnpm`・`yarn`・`bun` の `test`・`build`・`lint`・`typecheck`、`swift test`・`swift build`、`xcodebuild`、`cargo`、`go`、`pytest`、`tsc`、`jest`、`vitest`、`claude plugin test`・`validate` に当たる |
| `contextPercent` | `/handoff` を勧める文脈の割合（%）。初めは `70` |

正規表現が壊れている時は、初めの値で見て、最初のターンか最初の Bash でトーストで知らせる。数が正しくない時は、初めの値にする。
